## 2026-11-20 第一百五十轮：管理台不再「压缝」+ App 打开时不再转圈（v2.24 / 151）

**一、管理台的「缝隙」到底在哪（无头量出来的）**
用 1440×900 打开 `11111/public/admin.html` 量了一遍 `#view-overview`：`.stats` 与第一个面板之间是真实的 18px 空隙；而面板与面板之间 `top/bottom` 完全相接（450↔766、766↔1118），`.panel` 自身 margin 为 0 —— 也就是说**两个面板是贴死的**，交界处只剩各自 1px 边框 + 20px 圆角 + 外阴影，看上去像被压出一条缝。另外顶部导航条 `.topbar` 的背景是 `linear-gradient(rgba(11,11,18,.96), rgba(11,11,18,.86))`，底部 14% 是半透明的，滚动时下面的行会从它底下透出来，像一条糊住的白缝。`#serverKv .row` 里那串引导线是 `1px dotted rgba(255,255,255,.17)` 且左右各 10px 边距，本身就断成一小截一小截。

## 2026-11-20 第一百四十九轮：苹果版（iOS / IPA 工程）落地到 `ios-u/`

需求（用户 m17135 原话）：「把uapp做一个苹果的ipa软件，创建一个文件夹把跟苹果相关的文件放入」。

**为什么不是直接给一个 .ipa**
`.ipa` 里的可执行文件是 Mach-O，只能在装了 Xcode 的 macOS 上编译，装到 iPhone 上还必须签名（自己的 Apple ID 或开发者证书）。Windows 上没有 iOS 编译链，所以交付的是**完整可编译的 Xcode 工程 + 一键脚本 + GitHub Actions 工作流**，在 Mac 上一条命令出包，或者推上 GitHub 用免费的 macOS 机器出包。

**架构（照搬安卓的同构方案）**
安卓是 App 内起一个 HTTP 服务（`MainActivity.java:275` 的 `webView.loadUrl("http://127.0.0.1:" + port + "/index.html")`），页面与接口同源，前端 `UHost.*` 是原生 `@JavascriptInterface`。iOS 用同一套思路：`LocalServer.swift` 用 `NWListener` 在 `127.0.0.1` 起本地服务，静态文件取自 bundle 里的 `www/`，原生命令走 `/bridge/<方法>`，注入脚本 `Bridge.js` 用**同步 XHR** 调它 —— 页面与桥同源，同步语义和安卓完全一致，**app.js 一行没改**。

**目录（新文件夹 `ios-u/`）**
- `ios-u/U.xcodeproj/project.pbxproj`：手写工程（objectVersion 56，target `U`，9 个 Swift 源文件 + `Bridge.js` + `www` 文件夹引用 + `Assets.xcassets`）。
- `ios-u/project.yml`：等价的 XcodeGen 描述，想重新生成工程时用。
- `ios-u/U/AppDelegate.swift`：起窗口 + `WebViewController`。
- `ios-u/U/WebViewController.swift`：WKWebView（`allowsInlineMediaPlayback`、不需要手势即播放），`didFinish` 后 0.9 秒申请相册 + 相机，任一被拒弹提示后 `exit(0)`；`createWebViewWith` 让 `target=_blank` 同窗口打开。
- `ios-u/U/LocalServer.swift`：极小 HTTP 服务，路由 `/bridge/<name>`，其余走静态文件（目录或不存在的路径回落 `index.html`，路径含 `..` 返回 403），响应带 `Access-Control-Allow-Origin: *`。
- `ios-u/U/Bridge.swift`：`switch` 覆盖 29 个安卓桥同名方法；`enum ApkStore` 把 APK 存 `Documents/Downloads`（iOS 装不了 APK，`installApk` 只做定位）。
- `ios-u/U/Bridge.js`：注入脚本，`window.UHost` 全部方法用同步 XHR 打 `/bridge/`，带 `__ios:true`。
- `ios-u/U/Media.swift`：相册索引 `{id,name,mime,size,takenAt}`、读图（1280 / JPEG 0.78）、封面（640 / 360 两档），与安卓字段一致。
- `ios-u/U/CameraSnap.swift`：AVCaptureSession 前置静默抓拍，不开相机界面、`flashMode = .off`，失败原因 `busy/no-permission/no-camera/empty/error` 与安卓同一套码。
- `ios-u/U/Downloads.swift`：`URLSessionDownloadDelegate` 下载视频，进度写 `{state,got,total}`，完成后落 `Documents/Movies` 并用 `PHAssetCreationRequest` 存相册；删除时同时删文件与相册同名视频。
- `ios-u/U/CacheScan.swift`：扫 Documents / Movies / Downloads / Caches / tmp（深度 ≤6），输出 `{bytes,count,items:[{p,n,s,t,w}]}`，`delete` 真删。
- `ios-u/U/Device.swift`：设备信息、`refreshInfo`（`UIScreen.maximumFramesPerSecond`）、`localIp`（getifaddrs）、`rescanServer`（扫同网段 1–254 的 `:8787/api/config`）。
- `ios-u/U/Info.plist`：版本 2.23 / 150、`UIFileSharingEnabled`、四项权限文案、ATS 允许局域网明文、`UIRequiresFullScreen`。
- `ios-u/U/Assets.xcassets`：`icon-1024.png`（1024×1024 紫渐变 U）+ 紫色 AccentColor。
- `ios-u/scripts/build-ipa.sh`：`./scripts/build-ipa.sh` 出无签名 ipa；`TEAM_ID=xxx ./scripts/build-ipa.sh sign` 出可直接安装的签名 ipa。
- `ios-u/scripts/make-unsigned-ipa.sh`：已有 `.app` 时直接压 ipa。
- `ios-u/.github/workflows/ios.yml`：macos-14 上 archive + 打包，产出 `U-unsigned-ipa` 制品。
- `ios-u/README.md`：为什么没有现成 ipa、三种出包方式、三种安装办法、工程结构、与安卓的差异。

**静态自检（Windows 上能做的那部分）**
- 工程文件括号配对：`{}` 51/51、`()` 21/21；`Info.plist`、`U.entitlements` 用 `[xml]` 解析通过（26 key / 1 key）；三个 `Contents.json` JSON 解析通过；`icon-1024.png` PNG 头有效、99,021 B。
- `Bridge.js` 与 `Bridge.swift` 方法对齐：Swift 27 个 case，`Bridge.js` 27 个方法；前端 `host.*` 实际调用 19 个（`cacheDelete/cacheScan/clearWebCache/deleteApk/deleteApkEx/deleteDownloaded/deviceInfo/downloadMedia/downloadState/installApk/listApks/listGallery/listGalleryThumbs/listGalleryThumbsPage/openDownloadFolder/openDownloaded/readGalleryItem/requestSnap` 等）全部有实现。
- 复查时修掉 4 个真会致命的点：①`WKWebViewConfiguration` 上的私有 KVC `allowUniversalAccessFromFileURLs` 会抛 `NSUnknownKeyException` 直接崩（已删，页面走 http 不需要）；②`AVCapturePhotoOutput` 不强持 delegate，`PhotoDelegate` 被提前释放导致照片回调永远不来（改成 `pendingDelegate` 强持）；③`PHAsset.value(forKey:"filename"/"fileSize")` 是未定义 key，KVC 抛异常崩（改用 `PHAssetResource.originalFilename` + `responds(to:)` 后再读 `fileSize`）；④`CacheScan.delete` 的 `try? ... as? **和安卓版的差异**
- 装不了 APK：下载的 `.apk` 存 `Documents/Downloads`，能在「文件」App 里看到。
- 不能长期后台常驻：退到后台后相册上报与任务轮询暂停，回前台自动续上；远端拍照、同步封面需要 App 在前台。

## 2026-11-19 第一百四十八轮：数据文件页读出手机上的 U 相关缓存（网页 + App 全来源）

需求（用户 m16985 原话）：「修复不读取缓存，不管网页还是手机，不管是不是缓存在同一账号，都要读取到u相关缓存」。截图里数据文件页四项全 0、清理缓存写「暂无缓存，图片视频预览将按需生成」。

**根因**
`localMediaItems()` 原来只统计 IndexedDB 里帖子自带的 blob 和内存里的 `urlCache`。手机上的 U 相关文件其实散在四处：App 私有目录（`getCacheDir()`、`getCacheDir()/tw`、WebView 缓存）、系统「下载/U」、相册 `Movies/U`、浏览器 Cache Storage —— 这些都不在 IndexedDB 里，所以页面永远显示 0。无头复现：往 IndexedDB 塞一条带 blob 的帖子后立刻显示「共 1 个文件 / 图片 1 个 · 70 B」，证明统计通路没坏，缺的是数据来源。

**安卓桥（android-u/src/com/trae/u/MainActivity.java）**
- `@JavascriptInterface public String cacheScan()`：依次扫 `getCacheDir()`、`getFilesDir()/tw`、`getExternalFilesDir(null)`、系统「下载」、相册 `Movies/U`，返回 `{bytes,count,items:[{p,n,s,t,w}]}`；`p` 前缀 `n:`（文件路径）或 `c:`（content uri），`w` 是来源 `app` / `download` / `movie`。
- 辅助：`scanDir(dir,out,where,depth)`（深度上限 6）、`kindOf(name)`（mp4/m4v/webm/mov/mkv → video，jpg/jpeg/png/webp/gif/heic → image，其余 other）、`scanDownloadsDir()`（API 29+ 查 `MediaStore.Downloads`，`RELATIVE_PATH` 以 `download/u` 开头或文件名以 `U-` / `U_` / `U.` 开头；旧系统扫 `Download/U` 和下载根目录）、`scanMediaStore()`（API 29+ 查 `MediaStore.Video`，`RELATIVE_PATH LIKE 'Movies/U%'`）。
- `@JavascriptInterface public String cacheDelete(String pathsJson)`：接收 `n:`/`c:` 前缀的 JSON 数组，路径的走 `File.delete()`、content uri 的走 `getContentResolver().delete(...)`，返回 `{"ok":N,"fail":M}`。
- 编译坑：两个扫描方法里的 `JSONObject.put` 会抛 `JSONException`，方法体已用内层 `catch (Throwable)` 兜住，但方法签名仍必须声明 `throws org.json.JSONException`，否则 javac 报 10 个「未报告的异常错误」。

**网页端（app.js）**
- 新增 `scanNativeCache()`：探测 `window.UHost.cacheScan`，把返回条目映射成 `{id:'n:'+p, path, scope:'native', where, size, name, type}`。
- 新增 `scanWebCache()`：遍历 `caches.keys()` → `caches.open()` → `c.keys()` → `c.match(req)`，取 `content-length` 或 `res.clone().blob().size`，生成 `{id:'w:'+url, scope:'webcache', where:'web', size, name, type}`。
- `localMediaItems()` 末尾改为 `Promise.all([scanNativeCache(), scanWebCache()])` 合并去重后按大小倒序，帖子里的 blob、原生文件、网页缓存三条来源一起统计。
- 新增 `whereText(it)`：列表每行显示来源 ——「App 缓存目录 / 相册 Movies/U / 系统下载 / 网页缓存 / 帖子里的文件 / 预览缓存」。
- 新增 `CACHE_LIKE(it)`：`scope` 为 `cache`/`webcache`，或 `scope` 为 `native` 且 `where` 为 `app` 的才算「可释放缓存」；`cacheStats()`、`clearCache()` 都改用它。
- `deleteLocalSelected()`：先把选中项拆成原生路径与网页缓存键，原生走 `UHost.cacheDelete`、网页缓存走 `caches.delete`，随后照旧从帖子 media 里剔除并刷新列表。

## 2026-11-19 第一百四十七轮：键值行「中间分开」真正做全（虚线引导独立成节点）+ 服务器信息三列

需求（用户 m00031，承接 m00029 截图）：「把中间分开来，其他菜单也这样」——第146轮只给 `span:first-child` 加了 `::after` 虚线，实测标签和值还是贴在一起，要把这个分隔效果推广到管理台**所有**键值面板。

**根因（第146轮为什么没生效）**
`.kv .row .k` 是 flex item，它的宽度是 `auto`。在它身上挂 `::after{flex:1 1 16px}`，伪元素会把 `.k` 的 auto 宽度吃满，`.k` 自己长到顶住值，于是 `k.right === v.left`，虚线长度 0~几个像素。实测：`.k::after{display:none}` 后 `.k` 宽度 81px → 53px，证明多出来的 28px 全被伪元素占了。结论：**弹性占位不能放在 label 的伪元素里，必须是独立的兄弟节点**。

**改法（11111/public/admin.html）**
1. CSS 块（admin.html:453 起，到 `.ud-grow .n{min-width:0}` 前，注释 `/* ===== 第147轮 … ===== */`）：
   - `.kv .row .k{flex:0 0 auto;max-width:46%;white-space:nowrap;overflow:hidden;text-overflow:ellipsis;color:var(--dim)}`

   - `.kv .row .lead{flex:1 1 18px;min-width:8px;margin:0 10px;transform:translateY(-3px);border-bottom:1px dotted rgba(255,255,255,.22)}`
   - `.kv .row .v{flex:1 1 auto;min-width:0;text-align:right;font-weight:700;overflow-wrap:anywhere;word-break:break-word;line-height:1.45}`
   - `.kv .row:has(.k):not(:has(.lead)){gap:18px}`（兜底：万一某处没补上 lead 也不贴在一起）
   - `#serverKv{grid-template-columns:repeat(3,minmax(0,1fr));gap:12px 26px}`，1000px 以下两列、520px 以下一列
2. 行模板统一成三段：`<div class="row"><span class="k">标签</span><span class="lead"></span><span class="v">值</span></div>`，`.k`→`.v` 共 19 处（liveKv / dirKv / tunnelKv / portListKv / visitorKv / netKv / backupKv / serverKv）。

## 2026-11-18 第一百轮：改用 serveo 专属域名 u.serveousercontent.com（+ 隧道抗断、管理台压缩）

用户自己在 Serveo 控制台预留了专属域名 `u.serveousercontent.com`，要求服务器改为使用这个地址。顺带修掉三个真实问题。

### 一、公网地址换成专属域名（不再随机换名）

- 设置改为：`tunnelProvider=serveo`、`tunnelRemoteHost=u.serveousercontent.com`、`portMobilePublic` / `portDesktopPublic` = `https://u.serveousercontent.com`、`tunnelLocalPort=17880`、`tunnelAuto=true`。
- 清掉了之前误填在「自定义命令」里的 `ssh -R u.serveousercontent.com:80:localhost:3000 serveo.net`（端口 3000 根本不是 U 的端口，而且它会顶掉内置的 serveo 分支，导致隧道一直连不上）。
- 实际生效命令：`ssh ... -R u.serveousercontent.com:80:127.0.0.1:17880 serveo.net`，serveo 回 `Forwarding HTTP traffic from https://u.serveousercontent.com`。

### 二、三处隧道缺陷修复

1. **专属域名被过滤成乱码**：`tunnelStart()` 里子域只保留字母数字（`replace(/[^a-zA-Z0-9-]/g, '')`），`u.serveousercontent.com` 被压成 `userveousercontentcom`，转发必然失败 → 改为允许点、去掉首尾点、上限 80 字符。
2. **重启后抢不回域名**：Windows 上只 `child.kill()` 会留下孤儿 ssh 继续占着专属域名，新进程永远 `remote port forwarding failed for listen port 80` → `tunnelStop()` 改用 `taskkill /PID x /T /F` 连子进程一起杀；新增 `killStaleTunnels()`，启动时先清掉命令行里带 `serveo.net` / `localhost.run` 的残留 ssh（实测一次清掉 13 个）。
3. **保留域名不能被自动改名**：第 91 轮的「子域被占用就换 `-altN`」逻辑会把专属域名改成 `u.serveousercontent.com-alt1` 这种不存在的地址 → 域名里带点时跳过改名，只重试，且重试间隔拉到 ≥15 秒（serveo 侧释放旧会话要 30~60 秒，连太勤只会自己堵自己）。

### 三、管理台静态文件压缩（公网打开快一个数量级）

`server.js` 的 `serveStatic()` 原来直接 `readFileSync` 全量发送、无压缩无 ETag：`/admin.html` 167KB 明文，公网隧道下要 11 秒。现在：

- 文本类（html/css/js/json/svg）自动 `gzip`（level 6）并按 `文件+mtime+大小` 缓存压缩结果，最多 40 份；
- 带 `ETag`，命中 `If-None-Match` 直接 304；图片等二进制仍发原文件。
- 结果：`/admin.html` **167,171B → 42,597B（gzip）**，本地 2ms、公网 3.6 秒（原来 11.4 秒），二次访问走 304。

### 十四、token 卡「刷新」只读、清零要确认
- 原先「刷新 / 清零」两个小按钮共用一个绑定逻辑的写法容易误触：点刷新在界面上看起来像把数字清空了。现在拆成两个各自独立的行为，并用属性委托而不是靠 id 猜。
- 刷新（`[data-aiu="refresh"]`）：只发 `GET /api/admin/ai/usage`，一个写操作都不做；完成后把「已刷新：累计 8400 tokens · 36 次」读出来写进 toast，用户能立刻确认数字没变。
- 清零（`[data-aiu="reset"]`，按钮改成红色危险样式）：必须先在确认框里点确认才发 `POST /api/admin/ai/usage/reset`；确认框副标题会写上「当前累计 8400 tokens · 36 次」，清完 toast「已清零（原有 8400 tokens · 36 次）」。
- 实测（uitest/r103.js）：点刷新 → 数字 8400 tokens · 36 次前后完全一致，网络里只有两条 GET，没有 DELETE/POST；点清零 → 先弹确认框（标题「清零 token 账本？」，文案带当前累计），确认后才出现 POST /api/admin/ai/usage/reset，数字变 0 tokens · 0 次；全程 0 pageerror。

### 十九、真人评论 / 回复 AI 人机时，AI 读懂整段对话再回话（可无视间隔）
- 触发条件：真人在 AI 人机的帖子下评论，或者直接回复了 AI 的某条评论。游客、本地人机、其它 AI 账号说话都不触发（不会自己跟自己聊）。
- 读懂整段对话：服务器把这条帖子的正文 + 评论区全部留言按时间顺序（最多 40 条）拼成一段，标出哪几句是 AI 自己说过的（前标「（你）」），再点明「最后是 XX 在跟你说话」，交给新增的 `threadMessages` 提示词（aibot.js）：要求先理清谁在说什么、有没有分歧 / 玩笑 / 追问、自己前面说过什么，再用同一个人的口气回 10-40 字，禁止复读对方、禁止客套模板、禁止重复自己说过的话。
- 看图：如果开着「看图 / 看视频」，回真人时也会带最多 2 张图（720p 缩略图 / 视频封面），回复里能点出画面细节。
- 两个开关（管理台「AI 人机 → AI 能力与模型 → 跟真人对话」）：
  - **真人说话就回**（`aiReplyHuman`，默认开）：关掉就完全不理真人，只按自动轮转发内容。
  - **回真人不限间隔**（`aiReplyFast`，默认开）：打开时真人一说话 0.5 秒内就回，不受人机之间「隔几秒才能动一次」的节奏限制；关闭则按正常节奏等 3~8 秒再回。
- 防互刷：`aiReplyPerPost`（默认 3，0 = 不限）—— 同一条帖子每个 AI 人机 30 分钟内最多回几条；同一条留言只回一次（按 comments.id 去重）。
- 不拖慢真人：触发是在评论接口返回之后用 `setTimeout` 异步跑的，提示词或模型出错都静默跳过，真人评论照常 201 返回（实测 5ms）。

## 2026-11-17 第九十四轮：设置大改版、历史版本（APK 分发）、游戏大厅白边、返回提示

**这一轮解决什么**：设置页太挤（十几个功能平铺）、每次更新 APK 只能靠传文件、全屏游戏左上右上露出浅色圆角缺口（看着像白边）、安卓「再按一次退出应用」系统 Toast 自带应用图标。

### ① 游戏界面的「白边」其实是圆角缺口
- 根因：全屏游戏层沿用了通用 `.sheet` 的响应式圆角（`.lobby-sheet/.tear-sheet/.shooter-sheet` 没被覆盖），四角圆弧外侧露出页面浅色底，视觉上就是白边。
- 改法：index.html 的样式里加 `.lobby-sheet,.tear-sheet,.shooter-sheet{border-radius:0!important}`（`.jump-sheet` 原本就有这条）。实测 `#lobbySheet` 计算样式 `border-top-left-radius: 0px`，截图四角纯深色，无浅色缺口。

### ② 历史版本（服务器端 + App 端）
- 服务端 `11111/src/server.js`：
  · 新增目录 `data/versions/`（`VERSIONS_DIR` / `VERSIONS_INDEX=index.json`），索引结构 `[{id,version,versionCode,size,createdAt,note,file}]`，单包上限 `VERSION_APK_LIMIT = 400MB`，最多保留 40 个（超出按时间删旧文件）。
  · `GET /api/app/versions`：公开列表（App 端读取，`Cache-Control: private, max-age=15`）。
  · `GET|HEAD /api/app/versions/<id>/apk`：`serveVersionApk()`，`Content-Type: application/vnd.android.package-archive`、`Content-Disposition` 带 `filename*`、支持 `Range`（206 + `Content-Range`），下载计入流量统计。
  · 管理接口 `GET /api/admin/versions`、`POST /api/admin/versions`（读 `X-Version` / `X-Note` / `X-Filename` / `X-Version-Code`，流式写盘）、`DELETE /api/admin/versions/<id>`。
  · CORS 允许头补 `X-Version,X-Version-Code,X-Note,X-Ratio,X-Upload-Id,X-Chunk-Index,X-Chunk-Total,X-Total-Bytes`。
  · **请求头只能放 ISO-8859-1**：新增 `hdrText(v)`，对 `x-filename` / `x-version` / `x-note` 做 `decodeURIComponent`；客户端（app.js 两处上传、admin.html 上传）改成 `encodeURIComponent`。否则中文文件名/说明会让 `setRequestHeader` 直接抛 `TypeError`（上传必挂）。
- 管理台 `11111/public/admin.html`：新增「历史版本」标签（tab 数组与 `refresh()` 都加了 `versions`）。面板含上传表单（版本号 / 说明 / APK 文件 / 上传并发布）+ 进度条 + 表格（版本号、发布时间、内存大小、说明、文件、下载/删除），上传走 `XMLHttpRequest` 读 `upload.onprogress`。
- App 端 `app.js`：右滑菜单新增「历史版本」（`data-side="versions"` → `sideAction('versions')` → `openVersions()`），列表只显示 **发布时间 · 大小 · 说明**，点「下载」走 `downloadVersion()`：XHR `responseType=blob` + 行内进度条，完成后交给 `UHost.saveApkBase64()`（原生写系统下载目录），浏览器里则用 `a[download]` 落盘。
- Android `MainActivity.java`：`HostBridge` 新增 `@JavascriptInterface saveApkBase64(b64,name)` —— 后台线程 base64 解码，SDK≥29 用 MediaStore 写 `Downloads`（`RELATIVE_PATH=Download`），低版本写 `getExternalFilesDir(DIRECTORY_DOWNLOADS)`，完成后用页面内提示回报保存路径。
